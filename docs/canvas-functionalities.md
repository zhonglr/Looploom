User Question:
根据原版总结并细化，一个成熟的低代码产品应该有什么功能。你的回答要聚焦画布的功能，而不是对周围外设侃侃而谈。

AI Answer:
• 一个成熟的低代码画布，不是“把页面塞进 iframe，再允许拖拽”。它本质上是一个结构感知的空间编辑器：用户操作视觉对象，系统必须稳定、可预测地转换成结构变更。

  原版之所以好用，是因为它已经形成了完整反馈闭环：

  手势
  → 命中视觉对象
  → 推断结构意图
  → 显示操作预览
  → 校验是否合法
  → 原子提交
  → 明确反馈

  成熟产品应在这个基础上具备以下画布功能。

  ## 1. 完整的画布视口控制

  画布世界和页面内容必须分离。页面是被编辑对象，画布是观察和操作页面的空间。

  必备功能：

  - 以鼠标指针为中心的连续缩放；
  - 明确的缩放范围，例如 20%–300%；
  - 放大、缩小、恢复 100%；
  - 适应整个画布；
  - 适应当前选区；
  - 空格拖动、鼠标中键拖动、抓手工具；
  - 滚轮平移，Ctrl/Cmd+滚轮缩放；
  - 触控板双轴滚动和缩放；
  - 拖拽到视口边缘时自动平移；
  - 页面内容高度变化后自动更新画布尺寸；
  - 每个页面分别保存 zoom、pan 和 scroll 状态；
  - 切换页面后恢复离开前的位置。

    （另一轮的答案）
  - 20%–300% 缩放、指针中心缩放、100%、适应画布；
  - 空格、中键、抓手工具平移；
  - 滚轮平移、Ctrl/Cmd+滚轮缩放；
  - 拖拽靠近边缘时自动平移；
  - 根据内容自动调整画布高度；
  - 横向、纵向、换行 Flex 的最近插入点计算；
  - 清晰的插入线和容器内部高亮；
  - 鼠标旁直接显示非法落点原因；
  - 双击文字原位编辑；
  - 选中后的浮动复制/删除工具条；
  - 容器缩放手柄；
  - 绝对定位拖动、对齐参考线、方向键微调；
  - Alt+方向键重排兄弟节点；
  - 拖入后的落位动画；
  - 明确的组件拖拽 ghost。

  必须只有一个明确的滚动所有者，不能出现外层工作区和 iframe 同时抢滚动的情况。

  ## 2. 稳定、可理解的节点选择

  选择系统必须回答两个问题：

  - 用户现在指的是哪个视觉对象？
  - 这个视觉对象对应哪个结构节点？

  必备功能：

  - Hover 时显示候选节点边界；
  - 单击稳定选中，不因子元素覆盖而随机变化；
  - 选中框在不同缩放比例下保持恒定可见尺寸；
  - 选中标签显示组件来源、类型和名称；
  - 文本、表达式、组件、容器具有不同身份；
  - 支持在嵌套节点之间切换：
      - 选择最深节点；
      - 选择父节点；
      - 在同一位置的候选节点间循环；

  - 点击空白区域清除选择或选择页面根节点，行为必须固定；
  - 选中对象离开视口时仍能定位回来；
  - Portal、弹层和组件内部包装 DOM 不得破坏选择。

  成熟能力还包括：

  - 锁定节点，避免误选；
  - 隐藏节点不参与普通命中。

  ## 3. 结构感知的拖拽与落点

  落点不能由“鼠标下面最深的 DOM”单独决定。它必须结合：

  - 被拖动节点类型；
  - 候选节点及其祖先链；
  - 容器布局方向；
  - 插槽合同；
  - 当前位置；
  - Schema 合法性。

  画布应支持：

  - 插入容器内部；
  - 插到节点之前或之后；
  - 同容器重排；
  - 跨容器移动；
  - 空容器插入；
  - 命名插槽插入；
  - 横向布局的左右插入；
  - 纵向布局的上下插入；
  - wrapped flex 中跨行插入；
  - Grid 单元格和轨道插入；
  - 复合组件的专用结构落点；
  - 拖到非法子节点时自动寻找最近合法祖先；
  - 拖动靠近容器边缘时明确区分“放进容器”和“放到容器外”。

  拖拽过程中不得连续修改文档。只能预览，松手后提交一次原子操作。

  ## 4. 清楚的拖拽反馈

  拖拽时，用户不应该猜系统准备做什么。

  画布至少需要四种不同反馈：

  - inside：目标容器整体高亮；
  - before/after：准确的插入线；
  - replace/wrap：明确的结构预览；
  - rejected：拒绝样式和具体原因。

  还应具备：

  - 精确的 drag ghost，显示真实组件身份；
  - 被拖节点降低透明度，但原位置仍然可辨认；
  - 插入线在移动时稳定过渡，不抖动；
  - 缩放后插入线仍保持适合点击和观察的尺寸；
  - 拖拽越过 iframe 边界时反馈不中断；
  - 松手成功后有克制的落位动画；
  - 操作失败后节点回到原位；
  - 非法原因跟随指针显示，例如：
      - “该插槽只接受文本”
      - “不能移入自己的子节点”
      - “该插槽已达到最大数量”
      - “这个组件只能放在 Tabs 中”

  绝不能静默失败。

  ## 5. 文档流与自由布局两套直接操作

  成熟低代码画布通常同时存在两种布局语义。

  ### 文档流节点

  - 拖动用于重排或换容器；
  - 尺寸由内容、父容器和布局约束决定；
  - 不能伪装成自由坐标移动；
  - 支持 Flex、Grid、Stack、Block 等布局。

  ### 自由定位节点

  - 鼠标直接移动；
  - 方向键进行精细位移；
  - Shift+方向键大步移动；
  - 对齐父容器和兄弟节点；
  - 显示水平、垂直和中心参考线；
  - 支持吸附开关；
  - 防止节点完全拖出可恢复区域；
  - 显示当前坐标和尺寸；
  - 可设置锚点、约束和定位参考系。

  画布必须明确当前节点属于哪一种模型，不能让同一个拖拽动作含义不确定。

  ## 6. 直接编辑能力

  高频操作应直接在画布完成。

  必备功能：

  - 双击文本原位编辑；
  - Enter 提交，Escape 取消；
  - 编辑时禁止节点拖拽；
  - 选中后显示浮动操作条；
  - 复制、剪切、粘贴、重复、删除；
  - 拖动缩放手柄修改宽高；
  - 保持宽高比；
  - 遵守组件的最小、最大尺寸约束；
  - 多选后整体移动和缩放；
  - 对齐左侧、右侧、顶部、底部和中心；
  - 水平、垂直均匀分布；
  - 包裹为容器；
  - 从容器中移出；
  - 在空插槽中直接触发添加操作。

  所有连续移动和缩放手势都只能生成一条 Undo 记录，而不是每个像素一条。

  ## 7. 响应式页面与视口模拟

  低代码画布编辑的是应用，不是静态截图。

  画布应支持：

  - 桌面、平板、手机视口预设；
  - 自定义宽高；
  - 自适应内容高度；
  - 横竖屏切换；
  - 断点切换；
  - 缩放和响应式视口相互独立；
  - 在当前视口隐藏的节点仍可诊断和定位；
  - 清楚区分基础值与当前断点覆盖值；
  - 在多个视口间比较同一节点的位置和布局；
  - 内容溢出、换行和滚动区域可视化；
  - 安全区域、固定定位和 sticky 行为的正确模拟。

  切换视口不能重建编辑会话或丢失选择。

  ## 8. Design 与 Preview 的严格边界

  两种模式应使用同一棵真实组件树，但交互策略不同。

  ### Design

  - 单击组件用于选择；
  - 表单控件默认不提交、不导航；
  - 链接不会离开编辑器；
  - 编辑 Overlay 可见；
  - 拖拽、缩放、原位编辑启用；
  - 用户可临时进入“与组件交互”状态。

  ### Preview

  - 编辑 Overlay 完全消失；
  - 组件恢复真实交互；
  - 表单、菜单、Tabs、弹层和导航正常运行；
  - 不允许删除、拖动或选中节点；
  - 页面滚动方式与实际应用一致。

  切换模式不应刷新 iframe、重建 React 树或丢失组件状态。

  ## 9. 事务、历史和操作结果

  画布的每个动作都必须返回确定结果：

  committed
  rejected
  no-op
  cancelled

  结果应包含：

  - command ID；
  - 操作类型；
  - 变更节点；
  - 新 revision；
  - 拒绝原因；
  - 是否可以撤销。

  历史能力包括：

  - Undo/Redo；
  - 移动、缩放等连续手势合并；
  - 选择、缩放、平移不污染文档历史；
  - 新操作后正确清除 redo 分支；
  - 撤销后恢复合理的选择状态；
  - 本地立即提交，后台异步保存；
  - 保存失败只能标记未同步，不能锁死画布；
  - 网络请求不得进入指针操作链路。

  宿主不能在 Canvas 确认之前显示“已插入”或“已移动”。

  ## 10. 键盘操作必须完整

  拖拽不能是唯一入口。

  至少需要：

  - Tab/Shift+Tab 遍历可编辑节点；
  - Enter 选择或进入编辑；
  - Escape 退出编辑、取消拖拽或清除选择；
  - Delete/Backspace 删除；
  - Cmd/Ctrl+D 重复；
  - Cmd/Ctrl+C/X/V；
  - Cmd/Ctrl+Z 和 Shift+Cmd/Ctrl+Z；
  - 方向键移动或导航；
  - Alt+方向键重排兄弟节点；
  - 快捷键选择父级、子级和同级；
  - 键盘选择目标插槽并移动节点；
  - aria-live 播报落点和拒绝原因。

  焦点进入 iframe 后不能被困住，也不能让 Shell 快捷键和组件自身快捷键互相抢夺。

  ## 11. Overlay 必须独立于用户组件

  成熟画布不能把编辑器样式直接污染到真实组件上。

  正确分层应是：

  真实组件渲染层
  ├─ Web
  ├─ Ant Design
  ├─ MUI
  └─ 用户组件

  编辑器 Overlay 层
  ├─ Hover
  ├─ Selection
  ├─ Handles
  ├─ Drop indicators
  ├─ Guides
  └─ Diagnostics

  Overlay 应根据节点几何绘制，而不是依赖给第三方组件直接加 outline、伪元素和编辑器 CSS。

  它还必须正确处理：

  - zoom/pan 坐标转换；
  - iframe 滚动；
  - ResizeObserver；
  - 动态内容；
  - Portal；
  - sticky/fixed 元素；
  - CSS transform；
  - 节点卸载；
  - 异步字体和图片加载。

  ## 12. 性能与稳定性

  成熟画布应保证：

  - 拖拽、缩放和平移接近 60fps；
  - 指针移动期间不重建整棵组件树；
  - Overlay 更新与文档提交分离；
  - 大页面不会因每次 hover 全树遍历而卡顿；
  - 几何信息按需缓存并在布局变化时失效；
  - 单个组件渲染失败不会拖垮整个画布；
  - iframe 断开后可恢复连接；
  - 页面切换不会串选中状态或 Undo 历史；
  - 拖拽取消、窗口失焦、Escape 后不会残留 shield、ghost 或 dragging 状态；
  - 不会因为快速连续操作产生旧闭包、乱序 revision 或失效目标。

  ## 成熟画布的最低验收标准

  一个画布只有同时满足以下条件，才能称为成熟：

  - 用户无需猜测当前选中了什么；
  - 用户无需猜测拖放后会发生什么；
  - 所有合法位置都容易命中；
  - 所有非法位置都有具体解释；
  - 缩放、平移、滚动和自动平移稳定；
  - 文档流、自由定位和响应式布局语义明确；
  - 每个操作都是原子的、可撤销的；
  - 鼠标和键盘都能完成核心编辑；
  - Design 与 Preview 不互相污染；
  - 页面越复杂，交互仍然保持可预测；
  - 任何新架构都不得让这些能力低于原版。

  原版还不是完整的成熟低代码画布，但它已经具备了正确的核心：视口控制、直接操作、布局感知落点和及时反馈。后续建设应该沿着这些能力向上扩展，而不是把它退化成“能点击、能拖一
  下”的组件预览器。
